# Boss 與飛彈：v32 後續修訂（待瀏覽器驗證）

基準是 PR #13 的 bd0243a7407bce10cc3e8e2ef1885b68624b9179，沒有合併或修改主線。

## 本次新改動

- 飛彈沿用原創 `hostile-missile-v2.webp`，顯示由 8×18 放大為 11×26，增加一個重用 Image 的深色輪廓與 7–12px 短推進焰。沒有預測線、歷史軌跡或新粒子。碰撞與速度未放大。
- 正式 renderer 重用一個 RocketPose 與固定六個頂點，不再逐顆逐幀建立座標陣列、物件與閉包。輪廓每顆多一個 quad；保留全域 4096/Image與Text局部 QuadSingle，不宣稱 draw calls 不增加。
- 第一關保留 P1 的 96px 練習空隙，P2 保留五向 plasma，P3 中央改為實體飛彈，保持原有射線數與四脈衝契約。
- 第二關 P2/P3 由仍存活的甲板炮輪流擔任瞄準飛彈主炮，其餘炮覆蓋固定側向航道；拆炮會改變下一輪角色。P3主炮雙飛彈由近乎平行的±0.02改為±0.16rad，避免放大後兩枚彈體長時間擠在6px雙管航道；不增加射線數。甲板全毀後原有可見艦首武器及三階段模式保留。
- 第三關由完整機械 gunship 機身與獨立旋轉反應爐組合，四片護甲分階段由 64×40、76×62 展開至 82×76 的橢圓半徑。末階段在換位時沿對角移動 100×60px，穩定後才開火。P3採4.4秒循環（0.8秒換位、3.6秒定點出招），避免短窗口反覆重設讓站定更安全。弱點是可見64px反應爐，接觸碰撞仍是載具本體。先破護甲、再打爐心的規則保留，沒有加血。
- 第三關 P3 先鎖定玩家位置射出飛彈，再以半拍延遲的左右分叉 plasma 壓迫；不是即時追蹤玩家或增加總射線數。保留停火換位、預先預留完整尾彈時間、死亡炮座取消等限制。

## 驗證狀態

- 建置與 typecheck 曾在開發中成功；交付必須以最終 head 的完整檢查為準。
- 初版22px弱點使部分正常路線達205秒時間限制（其中2026種子仍有3HP），不是存檔毀損。調整為對應64px可見反應爐的32px半徑後，原有8個正常Stage03路線全過，未放寬時間、HP或勝利斷言。
- 預設本機高平行測試有三條5秒逾時；改以單worker驗證同一套斷言，不修改CI或測試逾時。
- 支援的雲端預覽已實際開啟；Chrome 顯示 `Cannot create WebGL context, aborting`。因此這次預覽無法檢查遊戲畫面；沒有更換渲染器、登入Google或繞權限。後續需精確head CI的真WebGL瀏覽器影片／原生畫面。
- 真人手感、實體手機、聽感沒有驗證。模型通關、隔離展示、CI自動操作必須分開列出。

尚未取得最終CI／實頁證據之前，不部署覆蓋私人v32，也不宣稱美術、難度或效能驗收完成。
