# Boss 與飛彈：v32 後續修訂記錄

以下狀態是實作當下的歷史；最新精確head、CI、視覺覆核與私人部署以PR #13文首為準。

基準是 PR #13 的 bd0243a7407bce10cc3e8e2ef1885b68624b9179，沒有合併或修改主線。

## 本次新改動

- 飛彈沿用原創 `hostile-missile-v2.webp`，顯示由 8×18 放大為 11×26，啟動時把深色輪廓烘焙進同一張快取紋理，並使用 7–12px 短推進焰。沒有預測線、歷史軌跡或新粒子。碰撞與速度未放大。
- 正式 renderer 重用一個 RocketPose 與固定六個頂點，不再逐顆逐幀建立座標陣列、物件與閉包。輪廓不再多用一個Image／quad，仍是每枚一個池化Image；保留全域 4096/Image與Text局部 QuadSingle，不宣稱 draw calls 不增加。
- 第一關保留 P1 的 96px 練習空隙，P2 保留五向 plasma，P3 中央改為實體飛彈，保持原有射線數與四脈衝契約。
- 第二關 P2/P3 由仍存活的甲板炮輪流擔任瞄準飛彈主炮，其餘炮覆蓋固定側向航道；拆炮會改變下一輪角色。P3主炮雙飛彈由近乎平行的±0.02改為±0.16rad，避免放大後兩枚彈體長時間擠在6px雙管航道；不增加射線數。甲板全毀後原有可見艦首武器及三階段模式保留。
- 第三關由完整機械 gunship 機身與獨立旋轉反應爐組合，四片護甲分階段由 64×40、76×62 展開至 82×76 的橢圓半徑。末階段在換位時沿對角移動 100×60px，穩定後才開火。P3採4.4秒循環（0.8秒換位、3.6秒定點出招），避免短窗口反覆重設讓站定更安全。弱點是可見64px反應爐，接觸碰撞仍是載具本體。先破護甲、再打爐心的規則保留，沒有加血。
- 第三關 P3 先鎖定玩家位置射出飛彈，再以半拍延遲的左右分叉 plasma 壓迫；不是即時追蹤玩家或增加總射線數。保留停火換位、預先預留完整尾彈時間、死亡炮座取消等限制。

## 站定與主動操作的同策略對照

在相同seed42、30／60FPS、同一正常前段路線、持續射擊與161／168秒兩顆炸彈下，只於Boss進場後停止方向輸入。v32兩路均死亡；候選358fd743兩路反而HP1站定通關，故拒絕把較長戰鬥直接稱為挑戰已改善。調整P3定點窗口為完整3.6秒後，站定兩路皆HP0失敗，同時原8條主動正常路線與6條固定延遲觸控模型亦通過。這不是所有站位或種子不可掛機的保證，也不是人類手感。資料及中間失敗保留於boss-route-observations-nov20.json。

## 同版CI取證後的輪廓成本修正

b5355cad的PR CI44677326124已578 unit／41 E2E成功，取得artifact14604202659，ZIP SHA256 1c35263d9ed09bc171b4de60497cd3084088771b5a746106b8d8df94fd42aef9；58個build檔與本機完全相同。已看完整與展開機體、320px及正常飛彈實飛圖，但這不是之後快取修訂的最終驗證。

該版第二關Boss P3共有276個取樣幀，draw calls p95=123、RAF p95=50ms、飛彈提交峰值39（含畫面外緩衝區）；第三關P3為345幀、p95=66／50ms、峰值8。不是GPU時間，也不能與不同CI／路線的v32數字當作受控FPS比較。兩Image輪廓使每顆多一quad是可確認的額外成本，故改為啟動時一次性用原圖alpha烘焙52×112快取，顯示13×28（內部金屬本體仍11×26），之後每枚只使用一Image；尾焰仍兩個共享Graphics三角形。來源WebP不修改，沒有逐幀烘焙、粒子歷史或新外部素材。

新增快取重用／缺來源／缺Canvas context回歸，以及正常實戰診斷：實際sprite池索引差值計算renderedQuads，與rendered飛彈數相等，這是影像池呼叫數，包含邊界外緩衝區，不是實際GL draw calls；GL／RAF仍由獨立取樣器量測。模型、Boss、關卡資料、音訊、存檔及鎖檔相對b5355cad不變。必須對快取修訂重新跑完整精確head CI與實頁，不能用b5355cad綠燈代替。
