# 一般敵彈雙發與 Boss 四發連射

基準為 PR #9 的 `73839fd25bed3d7bb7ccfb53268665173326d34a`。本次不是從最初雛型計算倍數，也沒有新增追蹤導彈種類。

## 實作與邊界

- Stage 01 一般敵彈每條既有射線由單發改為雙發，Boss 每條射線由單發改為四發。發間隔 0.12 秒，分別持續 0.12／0.36 秒；保留攻擊輪次及 0.6／0.65 秒預告，不將預警時間除以四。
- 保留既有扇形角度、階段、速度及缺口，不再瞄準玩家第二次。後續彈從仍存活的同一發射器位置發射。擊破、離場、炸彈、Boss 階段切換、側炮破壞及重新開始會取消對應未發射彈；暫停凍結排程。
- 使用池化發射器的生成 ID，避免死掉後被新敵機重用時繼承舊連射。
- 未改玩家三生命、傷害、補給、炸彈數、Boss 血量、399 戰鬥機與 6 補給機、關卡時長、音樂、存檔。

## 可重現計數

`npm test -- tests/burst-density.test.ts`；隔離計數使用固定中央、無敵，只量化發射量，不代表玩家可原地存活。baseline 僅將 burst 設定回 1，對應上述 commit 原單發實作。

在相同 0–125 秒（Boss 出場前）時間窗、30／60／120 FPS：

- 不射擊：251→502、245→490、251→502，皆正好 2 倍。
- 持續射擊：89→178、85→164、81→158，約 2／1.93／1.95 倍。擊破發射器會取消尾發，所以實戰不是無條件補發兩倍。
- 不射擊敵彈峰值 18→34，沒有強制刪彈限流。

Boss 各階段固定血量、不攻擊 Boss、不破壞側炮，比較完整前八輪攻擊並等待最後一輪 0.4 秒。在每一組前後相同時間窗，30／60／120 FPS 均為：

- 第一階段 16→64 發（4 倍）；60 FPS 視窗約 21.87 秒。
- 第二階段 40→160 發（4 倍）；60 FPS 視窗約 21.73 秒。
- 第三階段 24→96 發（4 倍）；60 FPS 視窗約 16 秒。

這是發射數，不是傷害四倍或難度四倍。真實 Boss 戰會因破壞側炮、階段切換、炸彈及擊敗 Boss 而取消尚未發射彈。

## 驗證與測試調整

- 本機 202 unit、typecheck、build 通過，包含取消排程、暫停／重開、池重用、三武器完整通關與低幀率追幀。
- 為對應使用者明確要求增加彈量，一般段池預算 32→40、完整路線敵彈預算 24→48；不是偷偷停發彈或削減敵機。實測一般段峰值 34；保留 E2E 80 敵彈與既有實際效能上限。
- 重裝三條射線仍是三條，但各兩發，測試期望 3→6；護航三機各三線雙發，池上限 9→18。
- 舊 30 FPS 飛彈路線照原移動會死亡，因此示例控制改為 149 秒開始閃避 0.5 秒（中央路線向右、地面攔截後向左），集中射擊掃動路線增加低生命時使用既有炸彈的條件。沒有提高生命或關傷害，所有路線仍要求真正通關。
- 本機 Chromium 既知 socket EPERM，沒有繞限制。最終瀏覽器結果須讀精確 head CI，不能引用前版。真機、人工手感／趣味／難度未驗證，私人站部署另行核對。
