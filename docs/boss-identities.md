# 三關 Boss 的結構與動作修訂

基於已試玩的 PR #12 `d89b6e473d9d67dcdd8b9fdd43e13b0294dcca55`。Carl 的回饋是三關均像「一個主體兩個砲台」，動作呆板；本次不新增第四關、不合併依賴 PR、不部署。

## 設計與實作

| 關卡 | 結構 | 移動與出招 |
|---|---|---|
| 01 指揮艦 | 飛翼、兩座翼炮，沿用原素材 | 橫向編織、掃射；末階段蓄勢、俯衝、煞停射擊與回升，俯衝不發射 |
| 02 鐵閘守衛 | 單一縱長河艦，三座交錯甲板炮；艦尾艦橋為核心弱點 | 換航道時停火，左右定點分批齊射；炮管各自轉向，末階段前炮擴散封區 |
| 03 極地雷眼 | 圓形機械轉子、四片可破壞弧形護甲，沒有外掛雙炮 | 護甲每輪轉位60度後鎖定射擊；徑向外圈、核心瞄準及末階段扇形分工 |

`boss-rigs.ts` 定義這三種具體結構、連續路徑、碰撞和部件數；`boss-attacks.ts` 定義攻擊組合；`boss-muzzles.ts` 把警示和每發脈衝放在當下真實炮口；`boss-presentation.ts` 供正式遊戲和開發用展示共用。沒有引入通用 ECS。

保持原有核心 HP、各關部件總 HP、擊破部件造成的核心總傷害24、部件總得分500。部件分配改為2／3／4，不靠新增總血量製造差異。保留每串四發火力意圖與既有射速設定；完整警示和尾彈必須放得下停火窗口才開始下一串，因此不能把新動作的射擊間隔當成舊版逐秒完全相同。未宣稱所有種子絕對公平。

每串先保留至少0.65秒炮口充能，不畫未來彈道。第一關翼炮鎖定警示時看到的世界座標，每顆尾彈從移動後炮口計算至同一目標；仍保留96px目標間隔。河艦炮管在整串尾彈結束前保持該串瞄準，不因新串覆蓋。高速換位／護甲轉位時不出彈，避免來源追上先前子彈疊成一團。部件摧毀、炸彈、階段切換和重開會取消待發尾彈。

河艦甲板炮必須能被打中，不能讓整個長船身先吞掉本應命中甲板炮的子彈：艦橋為核心受擊區，整艦仍是接觸碰撞範圍。原始生成圖的三個插座與炮管轉軸各自校準；河艦炮口距轉軸22px，雙管橫向±3px。旋轉核心與護甲各自獨立繪製。

## 資產與效能限制

六張新 WebP 來自內建 image_gen 原創素材，完整／受損部件分別生成，提示與傳輸 blob 在 `boss-identities-generation.json`；最終檔案 hash、像素和轉軸在 `boss-identities-assets.json`。原 PNG 未提交到分支，但傳輸用未引用 GitHub blob 仍存在，不稱其不存在於 Git 物件儲存。匯入只做透明邊界裁切、尺寸及轉軸校準、WebP編碼，沒有用幾何圖層冒充原創機體。

保持 global batchSize4096，僅 Image/Text QuadSingle；正式繪圖仍使用既有 Image 物件池及受擊閃光機制。沒有逐幀重新生成機體大圖。舊關卡、波次、合法錄製 BGM、儲存格式與解鎖流程不變。

## 驗證狀態

已驗證：本機 npm ci、typecheck、正式 build；527 unit（55檔，maxWorkers=2）通過。新增涵蓋30／60／120 FPS的三階段路徑連續性、三種完整部件、有限值、位置界限、總血量／傷害／得分守恆、炮口與固定警示目標、部件取消及資產hash。測試發現河艦進場42px橫跳，已修成連續進場。原有第一關正常生命／輸入／三種武器、第二三關多種子觀測輸入路線保留；測試駕駛只依目前可見Boss位置追擊，沒有改生命、跳傷害或改時間。

尚未驗證：本次精確提交的完整瀏覽器E2E、實際WebGL／RAF、正常戰鬥影片及地炮可見／轉向／開火回歸、三關Boss完整與損傷動態目視、真手機與真人手感／音樂聽感。本機Playwright找不到正式Chromium；依具體錯誤嘗試官方安裝，仍下載0MiB／截斷ZIP，沒有繞過限制。CI結果尚未取得，不能沿用PR #12舊綠燈。
